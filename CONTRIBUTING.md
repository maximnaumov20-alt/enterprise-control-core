# Contributing to ECC

**Contribution status: discussion and issue reports only. External code contributions are not currently accepted for merging.**

ECC is still establishing its licensing and intellectual-property governance. The repository is public for transparency and review, but it does not currently publish a binding software licence or a contributor agreement.

## Before submitting work

- Open an issue to describe the proposed change and its motivation.
- Do not submit confidential, customer-owned, employer-owned, school-owned or otherwise restricted code or data.
- Do not copy code, documentation, images, fonts or other materials unless their origin and licence permit the intended use.
- Do not assume that opening a pull request grants ECC rights to distribute the contribution in Community and commercial editions.

## Security reports

Do not publish credentials, personal data, customer information or exploitable vulnerability details in public issues. Follow the private reporting options shown in the repository's **Security** tab when available. If no private reporting option is available, report only that a security concern exists and request a private contact channel; do not post exploit details publicly.

## When contributions reopen

The maintainers will publish the applicable Community licence, third-party notices, contribution terms and review process first. Any required contributor agreement or certification will be presented before code is accepted. The exact scope of contributor permissions will be stated in those terms.

## Review expectations

Once code contributions are enabled, changes will require review for correctness, tests, tenant isolation, authorization, migrations, security impact, dependency licensing and documentation. A passing CI run is necessary but does not by itself establish production readiness.
